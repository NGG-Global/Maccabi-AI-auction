# רשימת בדיקות ידניות לפני אירוע אמיתי

לבצע על הפריסה האמיתית (Vercel + הפרויקט המשותף), עם הלפטופ שיוקרן ועם
טלפון אחד לפחות. מומלץ לבצע את כל הרשימה יום לפני האירוע, ואת סעיפים 6 עד 9
שוב בבוקר האירוע.

## 1. תשתית

- [ ] המיגרציות 010 ו-011 הורצו על הפרויקט המשותף (ראו שאילתת הבדיקה המקדימה בכותרת של 010).
- [ ] ה-bucket `auction-logos` קיים (`npm run create-logo-bucket` או בדשבורד של Supabase).
- [ ] משתני הסביבה `NGG_STAFF_PASSWORD` ו-`NGG_SESSION_SECRET` מוגדרים ב-Vercel, ו-`ADMIN_PASSWORD` הישן הוסר.
- [ ] הסכמה `auction` מופיעה תחת Data API → Exposed schemas.

## 2. כניסת צוות

- [ ] `/admin` ללא cookie מפנה למסך הכניסה.
- [ ] כניסה עם מייל שאינו `@nggconsult.com` נדחית.
- [ ] כניסה עם סיסמה שגויה נדחית, ואחרי 10 ניסיונות כושלים מתקבלת חסימה זמנית (429).
- [ ] כניסה תקינה מובילה לרשימת החדרים, והמייל מוצג בכותרת.
- [ ] כפתור "התנתקות" עובד ומחזיר למסך הכניסה.
- [ ] קריאה ישירה ל-`/api/admin/rooms` ללא cookie מחזירה 401.

## 3. יצירת חדר

- [ ] יצירת חדר חדש: כותרת, שם לקוח, slug מוצע אוטומטית וניתן לעריכה.
- [ ] הוספה, עריכה, מחיקה וגרירה לסידור של היגדים; שמירה ללא קטגוריה נחסמת.
- [ ] העלאת לוגו PNG/JPG/WEBP מוצגת בתצוגה המקדימה; קובץ SVG או קובץ מעל 2MB נדחים.
- [ ] שכפול חדר קיים יוצר טיוטה חדשה עם אותם היגדים ואותו לוגו.
- [ ] מחיקת טיוטה שלא הופעלה עובדת; חדר שנוהל בו משחק מציע ארכיון בלבד.

## 4. הפעלה ומסך מוקרן

- [ ] "הפעל חדר" מעביר למסך החי `/admin/rooms/<id>/live`, והתג מראה "חדר פעיל" עם 12 שעות.
- [ ] ה-QR במסך פותח `/join?room=<slug>` ומציג את הלוגו ושם הלקוח.
- [ ] כפתור "העתקת קישור" מעתיק את כתובת ההצטרפות הנכונה.
- [ ] "הארך ל-12 שעות" ו"סיים" משנים את התג מיד.

## 5. הצטרפות משתתפים

- [ ] הצטרפות מטלפון: שם, קבלת מספר המטבעות שהוגדר בחדר (לא בהכרח 1,000).
- [ ] מונה המשתתפים במסך המוקרן עולה בזמן אמת.
- [ ] כניסה לחדר בסטטוס טיוטה / הסתיים / ארכיון מציגה הודעה מתאימה בעברית ולא טופס הרשמה.
- [ ] סריקה חוזרת מאותו טלפון מציעה "חזרה למשחק".

## 6. מצב מכירה פומבית

- [ ] פתיחת סבב: ההיגד מופיע על המסך ובטלפונים תוך שניות.
- [ ] אם הוגדר משך סבב: ספירה לאחור מוצגת, ובסיומה "הזמן נגמר" ללא סגירה אוטומטית.
- [ ] הצעה, העלאת הצעה, הצעה נמוכה מהקודמת (נדחית), הצעה מעל היתרה (נדחית).
- [ ] שוויון: שני משתתפים על אותו סכום, המוביל הוא מי שהגיע ראשון, וכך גם הזוכה בסגירה.
- [ ] סגירת סבב: הכרזת זוכה, רק הזוכה מחויב, היתרות בטלפונים מתעדכנות.
- [ ] לחיצה כפולה על "סגור סבב" אינה מחייבת פעמיים.
- [ ] פתיחת סבב שני בזמן שסבב פתוח נחסמת.

## 7. מצב חלוקת תקציב

- [ ] פתיחת החלוקה פותחת את כל ההיגדים יחד.
- [ ] שמירה אוטומטית של החלוקה, חריגה מהיתרה נחסמת.
- [ ] בזמן שהחלוקה פתוחה המסך המוקרן מציג השתתפות בלבד, לא סכומים.
- [ ] סגירה: תוצאות לפי היגד, זכייה משותפת בשוויון, כל ההקצאות מחויבות.

## 8. בידוד בין חדרים (שני חדרים פעילים במקביל)

- [ ] הצעה בחדר א' אינה מופיעה במסך החי של חדר ב'.
- [ ] טלפון שהצטרף לחדר ב' ומנסה להיכנס ל-`/play?room=<slug של א'>` מקבל הודעה שאין פרטי משתתף לחדר זה.
- [ ] איפוס חדר א' משאיר את חדר ב' שלם (משתתפים, סבב פתוח, הצעות).

## 9. איפוס ופרופיל

- [ ] איפוס דו-שלבי מהמסך החי מוחק רק את המשתתפים והסבבים של החדר, וההיגדים חוזרים לזמינים.
- [ ] אחרי איפוס, הגדרות המשחק (סוג, מטבעות, היגדים) ניתנות שוב לעריכה.
- [ ] `/profile?room=<slug>` מציג יתרה, הוצאה, זכיות וארכיטיפ.
- [ ] טאב "תמונת מצב": תקציב התחלתי = מספר משתתפים × מטבעות החדר.

## 10. ביום האירוע

- [ ] החדר הופעל בבוקר (חלון 12 שעות מתחיל מההפעלה, לא מהיצירה).
- [ ] QR מודפס מפנה ל-slug הנכון.
- [ ] הלפטופ המוקרן מחובר לרשת יציבה; הריענון הידני של המסך החי שומר על מצב המשחק.
